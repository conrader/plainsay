开源、透明、安全

在这里，信任不是一句口号——而是你可以亲自去读的东西。整个客户端都以 MIT 许可开源公开：处理流程、HUD、设置，全部都是。不是「开源核心」，也不是「现在开放、以后关闭」——你可以自由地 fork、修改，并无限期自行托管。

开放的部分

整个听写客户端——转录、编辑、HUD、设置、设置助理。在设备端运行的 Plainsay 不会发起任何你未主动要求的网络请求：没有数据分析、没有遥测、没有偷偷回传。

不开放的部分

付费 Cloud 套餐的计费后端——它保存着支付凭证和服务商凭证，正因如此才需要保持独立和私密。你实际使用的听写体验本身是完全开放的。

说出来，写下来

你说的

呃就是那个我们能不能把明天的站会挪到十点半左右因为我早上有个看牙医的事

Plainsay 写下的

我们能把明天的站会挪到 10:30 吗？我早上有个牙医预约。

清理这一步会去掉口头禅和重新起头的话，修正标点，并保留你实际说的措辞——它不是重写。转录/编辑的提供方可以更换（Gemini、OpenRouter、OpenAI、Claude，或自定义端点），也可以完全关闭，一旦失败就会回退到原始转录文本，而不是让整次听写失败。

为什么选择 Plainsay

可靠性

一次听写绝不会悄悄丢失。

编辑失败——没有密钥、没有网络、超时

自动回退到原始转录文本，并在 HUD 中提示。

没有可粘贴的焦点位置

文字会保留在剪贴板中，HUD 会提示按 ⌘V。

录音过程中崩溃或被强制退出

音频会在转录前先暂存到磁盘，并在下次启动时恢复。

粘贴因其他原因失败

听写内容早已写入本地历史记录——写入时间早于尝试插入之前。

即将推出

完整的实时输入已经上线，作为实验性选项——设置 › 语音 › 实时输入（默认关闭）。它放弃了“先清理、再一次性插入”的保证，换来一种实时的感觉：粗糙的文字在你仍在说话时就直接出现，清理完成后再就地修正。

此外：语言自动检测方面的持续工作，以及随着本地模型不断进步而调整的默认模型。
